## Problem: Color Discontinuities at Tile Boundaries

CLISAPP shows visible color seams/banding at tile boundaries when viewing Queensland region (zoom 8-12). Tiles look mismatched at edges.

## Root Cause Analysis

The tile generator extracts each 256x256 tile independently from the GeoTIFF:
- Source data: 0.45° resolution grid (very coarse ~50km spacing)
- At zoom 8: each tile is ~0.14° wide
- At zoom 12: each tile is only ~0.009° wide

When `_extract_tile_data` extracts a window for each tile and applies bilinear resampling, adjacent tiles extract overlapping but slightly different windows. The bilinear interpolation at tile edges produces different values because each tile only sees its own window boundary - creating visible seams.

## File to Fix
`CLISApp-backend/data_pipeline/processing/common/generate_tiles.py`

## Key Code Sections

**Current tile extraction** (lines 224-265):
```python
def _extract_tile_data(self, src, zoom, x, y):
    lat_max, lon_min = self.num2deg(x, y, zoom)
    lat_min, lon_max = self.num2deg(x + 1, y + 1, zoom)
    
    window = rasterio.windows.from_bounds(lon_min, lat_min, lon_max, lat_max, src.transform)
    data = src.read(1, window=window)
    
    if data.shape != (256, 256):
        # reproject with bilinear resampling to 256x256
        reproject(..., resampling=Resampling.bilinear)
    return data
```

**Color mapping** (lines 145-191): Linear interpolation between color breaks per pixel.

**Missing fill** (lines 193-218): Fill 0/NaN with adjacent pixel mean within tile only.

## Required Fix: Buffer-Based Tile Extraction

**Solution**: Add a buffer zone when extracting tile data:
1. Extract tile with N pixel buffer on each side (e.g., 4 pixels = buffer_pixels=4)
2. Resample the buffered area to (256 + 2*buffer) x (256 + 2*buffer)
3. Apply color mapping to the full buffered array
4. Crop out the center 256x256 pixels for the final tile

This ensures tile edges use bilinear interpolation with context from adjacent tiles, eliminating seams.

**Additional improvement**: Pre-warp GeoTIFF to Web Mercator (EPSG:3857) before tile generation for proper tile coordinate alignment.

## Implementation Request

Please implement the buffer-based fix in `generate_tiles.py`:

1. Add `buffer_pixels: int = 4` parameter to `PM25TileGenerator.__init__`
2. Modify `_extract_tile_data` to:
   - Expand tile bounds by buffer_pixels on each side (convert pixels to degrees)
   - Extract and resample to (256 + 2*buffer_pixels) x (256 + 2*buffer_pixels)
   - Return the full buffered data
3. Modify `generate_tile` to:
   - Apply `fill_missing_with_neighbor_mean` on the buffered data
   - Apply `apply_pm25_colormap` on the buffered data
   - Crop the center 256x256 pixels: `rgba_data[buffer:buffer+256, buffer:buffer+256]`
   - Save only the cropped 256x256 as the tile PNG

Also ensure `fill_missing_with_neighbor_mean` runs multiple passes (3-5 iterations) to fill larger gaps.

- The fix should work for all 5 layers (pm25, temperature, humidity, uv, precipitation)
